# FoldSpace · 折境空间

折叠屏半展开时，在上半屏运行视频、下半屏运行游戏，提供按需双开、四宫格目录与视频手势控制的独立 Android 实验应用。

当前版本 **0.6.3（正式发布）**，包名 `com.mkf.foldspace`。2026-10-27 将同版本预发布转为正式 Release，安装包与签名保持不变。先前版本主要在 OPPO Find N2 / Android 16 / ColorOS 16.0.5 上验证；0.6.3 的后台退场与贴边侧栏尚待真机确认。需要用户启动并授权 **Shizuku**，无需 Root。

> 已知问题：抖音在全屏与上半屏之间切换后，同一条视频仍可能从头播放。先前的恢复尝试未通过真机接续测试，0.6.3 不声称修复该问题。

## 功能

- 铰链角度处于 **110°–140°（含边界）连续 3 秒**时自动进入；范围外连续 3 秒自动退出。跨越边界重新计时。
- 自动进入时优先接入物理屏幕上的前台应用，退出时尝试将任务放回主屏后台，避免将视频或游戏置前；桌面、系统界面及本应用显示视频目录。
- 应用目录新增视频、游戏两个分区，按系统游戏分类／游戏标记及常见平台识别，每页 2×2 卡片，左右翻页。
- 普通点击仅打开所选应用，视频在上半区、游戏在下半区；单开时更换分类会收起另一应用。
- 点击“双开”或播放页“游戏双开”后进入组合模式，分别向对应分区传递多指触摸与返回；组合模式中更换一边会保留另一边。
- 保存的搭配仅在点击“双开”时选用。自动悬停只接入当前前台应用，忽略旧版默认开启的双开设置，不会额外启动记住的应用。
- 半展开只进入悬停界面，不自动请求横屏；目录、播放页、双开工具栏和设置页均有“横屏”按键，横屏按钮采用阅读页的 Activity 方向方式：悬停时保留现有界面，由独立全屏页持有方向请求；旋转确认前显示“旋转中”，按原生模式和旋转值确认物理屏幕横向稳定后显示“还原”，超时则提示并撤回。再点“还原”或退出时结束请求，不记住上次方向。
- 展开或收起时先完成后台任务归还，再结束手动方向页并移除悬停窗口；不主动启动桌面或把本应用切到前台。
- 双开／游戏页工具改为右边缘竖向手柄，点击展开可滚动的侧边栏，支持返回、目录、单屏、横屏与设置，点击顶部箭头收起。
- 上半区左右滑动切换视频应用，每次手势最多切换一个，带定向滑出／淡入动画；上下滑动和多指触摸保留给目标应用。下半区游戏不随视频切换重建。
- 本应用按钮、应用卡片、权限入口和开关使用液态玻璃风格，复用 [AndroidLiquidGlassView](https://github.com/QmDeve/AndroidLiquidGlassView) 的 MIT 开源 AGSL 着色器，加入背景采样、折射色散、光泽边缘及按压回弹。
- Android 13 及以上不再申请通知权限，自动悬停监测的常驻通知不显示在通知栏；系统后台活动列表仍可显示前台服务。
- 未开启游戏时，视频应用下半屏为无中央文字的手势触控区；抖音可通过下半屏上下滑动切换视频。已删除独立进度条和校准入口。
- 设置入口统一位于下半屏右侧，以同风格的半透明圆角面板打开二级设置，不重建上方应用窗口。
- 上半屏进入应用、切换应用和返回目录时使用淡入与轻微位移；下半屏控制区保持位置。
- 沉浸全屏显示，支持系统边缘手势临时唤出系统栏。

这是独立实现，不包含 OPPO 官方软件的代码或资源，也不修改抖音、哔哩哔哩等目标应用。没有实现视频与评论的原生上下屏重排。

## 安装与使用

1. 从 [v0.6.3 发布页](https://github.com/Promise0102/FoldSpace/releases/tag/v0.6.3) 下载签名 APK 和 `SHA256SUMS` 校验文件，或按下文从源码构建。构建输出为 `output/foldspace-0.6.3-signed.apk`。
2. 安装并启动 [Shizuku](https://shizuku.rikka.app/)，授权折境空间。
3. 打开折境空间，在设置中开启自动悬停并允许悬浮窗。
4. 在正在使用的应用中，将手机保持在 110°–140°约 3 秒，等待自动接入上半屏；完全展开等范围外位置保持 3 秒退出。

也可以在折境空间四宫格中选择视频或游戏，或点击“双开”启动默认组合。双开右边缘“‹”手柄展开侧边栏，可切换视频／游戏目录、手动横屏、分别返回、恢复视频单屏或打开设置。上半区左滑切到下一个视频应用、右滑切到上一个，依照视频目录顺序循环。目录和设置覆盖下半区时，不移除游戏或上方视频的显示会话。单屏触控区“返回”轻点向上方应用发送返回，长按回到视频目录；“游戏双开”进入游戏选择。使用设置页返回按钮或系统返回关闭二级设置。视频进度如需操作，可直接使用上方应用自身提供的控件。

更新后打开一次折境空间；若此前已开启自动悬停，会恢复监测服务。系统强行停止应用、限制后台服务或停止 Shizuku 后，需要重新启动相应服务。

## 构建

Windows + PowerShell 7、JDK 17 或更高版本、Android SDK。无需 Gradle。SDK 需要 Build Tools **36.0.0** 及 Android **API 37** 平台；脚本兼容平台目录 `android-37` 和 `android-37.0`。

设置 `JAVA_HOME` 和 `ANDROID_HOME`（或 `ANDROID_SDK_ROOT`），然后在项目根目录执行：

```powershell
pwsh -File ./scripts/Test-FoldSpaceControls.ps1
pwsh -File ./scripts/Build-FoldSpace.ps1
```

构建时核对 `foldspace/libs/dependencies.json` 中固定的依赖哈希。首次本地构建会在忽略提交的 `signing/` 中生成自己的签名密钥，APK 输出到 `output/`。请妥善保留密钥；自行生成的签名不能直接覆盖 Releases 中使用其他证书签名的安装包。

已有同名安装包时脚本拒绝覆盖。需要在其他目录构建可使用：

```powershell
pwsh -File ./scripts/Build-FoldSpace.ps1 -OutputDirectory ./build-output
```

可通过 `-BuildToolsVersion`、`-AndroidPlatform` 参数指定本机 SDK 版本。`-Version` 必须与源码 Manifest 一致。

## 验证与限制

自动检查包括 46 项折叠范围及持续计时断言、2041 项进度坐标断言、15 项播放恢复条件断言，以及 13 项应用分类／分区断言、2515 项独立会话及过期释放断言、55 项窗口方向生命周期断言、26 项一次手势切换一个应用及原生手势保留断言、15 项原生屏幕方向确认断言、50 项后台归还顺序与非破坏清理断言。已完成资源 / Java / DEX 编译、签名和 ZIP 对齐检查。

Find N2 真机确认了上半屏显示抖音、视频目录、自动进入与退出、现有任务移动。进度接续测试未通过，其他折叠设备、全部视频内容及长时间后台运行尚未全面验证。详见 [验证记录](docs/VALIDATION.md) 和 [更新记录](docs/CHANGELOG.md)。

0.6.3 尚未验证真机后台归还、贴边侧栏、Activity 横屏、显式双开、液态玻璃效果及通知隐藏、游戏帧率、多指操作及手动方向还原。部分游戏可能拒绝辅助显示、失焦暂停或抢占音频焦点；受保护视频可能黑屏。双开指两个不同应用同时显示，不复制账号或同一应用的数据。

后台归还使用系统任务容器事务，部分系统可能限制相关接口；失败时会在移除临时显示区后尝试将任务置后，此回退仍可能出现短暂前台变化。

目标应用可能在显示区、屏幕尺寸或其他配置变化时重建页面。Shizuku 授权不保证目标应用保留播放状态，也不能让未提供进度的内容自动支持跳转。

## 权限与数据

- 悬浮窗用于半展开界面，前台服务用于持续监听铰链传感器；仍按 Android 要求提供服务通知对象，但不申请通知展示权限。Android 12 及以下仍可能显示服务通知。
- Shizuku 用户服务以 shell 权限创建临时显示区、移动应用任务，并向目标应用传递触摸、返回和进度操作。手动横屏由点击触发的 Activity 方向请求完成；Shizuku 服务只在发现 0.5.0 遗留恢复日志时尝试一次清理。
- 应用不申请联网权限。最近使用、搭配选择与设置保存在本地；技术诊断仅保存在应用自己的外部文件目录。
- 仓库不包含签名私钥、设备日志、用户截图、原始厂商 APK 或反编译产物。
